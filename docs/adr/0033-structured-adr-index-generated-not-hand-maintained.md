# 0033 — The ADR decision index is generated from a structured YAML source, not hand-maintained markdown

> **Decision (Y-statement):** In the context of `docs/adr/README.md`'s "## Index" bullet list
> duplicating each ADR's number and title as a second, hand-maintained copy, facing the same
> drift class a sibling codebase's governance tooling hit for real (its own index table listed
> stale statuses weeks after the ADRs themselves changed, caught only by an external code-review
> tool because its own presence-only lint check never verified the details next to an ADR's
> number were still accurate), we decided to generate `docs/adr/index.yaml` as the structured
> source of truth on every audit run and render README's list from that same data between
> markers, with a new blocking lint check failing CI/pre-push if either drifts from the real ADR
> corpus, to achieve an index that cannot go silently stale the way two independently-maintained
> copies of the same facts always eventually do, accepting a new generated artifact and a
> stricter blocking check in exchange.

## Context

`docs/adr/README.md`'s "## Index" section listed every ADR as a bullet — `- [NNNN —
Title](file.md)` — a second, hand-written copy of data (number, title) that already lives
structurally in each ADR's own header/title line. Nothing generated this list or checked its
contents against reality beyond a `checkReadmeIndex` lint check that only verified an ADR's
number appeared *somewhere* in the README's text, never that the *title next to it* was still
accurate — the same weak-coverage shape found and fixed for real in this session's other
governance-tooling work.

A structural incident in this exact shape was found and fixed in this repo's own tooling package
(`packages/adr/`, ported from the same effort as the whole-repo scan / Realized-by hash-tracking
work): the sibling repo's index *table* (which also carries a Status column, unlike this repo's
title-only list) had drifted — two ADRs' listed status no longer matched their own files — caught
only by an external code-review tool. This repo's own list doesn't carry a Status column today,
so it was not directly exposed to that specific incident, but the underlying mechanism (a
hand-maintained second copy of ADR facts, checked only for presence) is identical, and this repo's
own `checkReadmeIndex` had exactly the same weak-coverage gap.

## Considered options

| Option | Pros | Cons |
|---|---|---|
| Extend `checkReadmeIndex` to compare each entry's title against the real ADR title | Small, bounded change; no new file format | Still a hand-maintained copy of the same facts; markdown lists remain hard for anything else to consume programmatically |
| Leave the list as-is (title-only, lower drift surface than a Status-column table) | No work | Doesn't scale if a Status/Date column is ever added later; the presence-only check still can't catch a title going stale, only an ADR going missing entirely |
| **Generate a structured `index.yaml` as the real source of truth; render README's list from it; block on staleness in either (chosen)** | One real source of truth, addressable by any tool without re-parsing markdown prose; README stays in its own existing readable bullet-list style; a real blocking check instead of a presence-only warning; matches the same fix already shipped in this repo's own tooling package's sibling port, so both stay in sync | A new generated file and a new blocking check to maintain; requires every ADR-touching change to be followed by re-running the audit before pushing (already true for Embodiment/drift, this just extends it) |

## Decision

`docs/adr/index.yaml` is the single generated source of truth for the ADR index — one entry per
ADR (`number`, `file`, `title`, `status`, `date`, so the structured artifact carries more than
the rendered list currently shows), sorted by number, regenerated by `packages/adr/adr-audit.ts`
on every run (the same step that already regenerates `docs/adr-audit/report.md`/`summary.json`,
except this one is committed, not gitignored, since it's meant to be browsable without running
the tool). A JSON Schema (`docs/adr/index.schema.json`) documents and validates its shape,
referenced via a `# yaml-language-server: $schema=...` comment for live editor validation.

`docs/adr/README.md`'s own "## Index" section no longer hand-maintains its bullet list. It
instead holds a short pointer to `index.yaml` plus the rendered list spliced between
`<!-- ADR-INDEX:START -->` / `<!-- ADR-INDEX:END -->` markers, regenerated from the exact same
in-memory data as `index.yaml` on every audit run — kept in this repo's own existing list
style (not reformatted into a table), since the rendered view should match what this repo's own
readers are already used to, not the sibling repo's visual convention.

`packages/adr/lib.ts`'s `lintAdrDir` gains a new blocking check (`checkIndexFreshness`, replacing
the old presence-only `checkReadmeIndex`): it recomputes what `index.yaml` and README's list
*should* currently say and fails with an `ERROR` if either the committed `index.yaml` or the
committed README list doesn't match — i.e., someone changed an ADR's title/status/date and
forgot to re-run the audit before pushing.

## Consequences

**Positive:**
- The index can no longer silently drift — CI/pre-push fails the moment it does.
- `index.yaml` is a real, schema-validated, machine-addressable artifact carrying more structured
  detail (status, date) than the rendered README list currently shows — available to any future
  tool without re-parsing markdown prose.
- README's reading experience is unchanged; only how the list gets there changes.

**Negative / trade-offs:**
- A new generated file and a new blocking check to keep working correctly.
- Anyone editing an ADR's header fields must remember to re-run the audit before pushing, same
  as already true for Embodiment/drift.

**Neutral / follow-up:**
- This ADR's own regeneration mechanism was itself found to have a real edge-case bug during
  implementation — the marker-splicing regex required two newlines between the START/END markers
  even when the content between them is genuinely empty (the shape a freshly-added marker block
  has before its first regeneration), and silently misreported that shape as "markers missing"
  rather than "content stale." Fixed before this ADR's own `Realized by:` locators were finalized;
  covered by a dedicated regression test in `lib.test.ts`.
