## Frontend Direction

The TanStack Router app in `apps/frontend` is deprecated. Do not add new features, routes, or UI work there. Build human web product work in `apps/web` moving forward. Use `apps/frontend` only for narrowly scoped legacy maintenance.

## Design System

The design system (`packages/design-system`) is built with Clafoutis. **Never edit the autogenerated files directly.** Always edit the source token JSON files and then regenerate.

### Source token files (edit these)

- `packages/design-system/tokens/colors/components.json` - Light mode component tokens (badge, button, alert, etc.)
- `packages/design-system/tokens/colors/components.dark.json` - Dark mode overrides
- `packages/design-system/tokens/colors/semantics.json` / `semantics.dark.json` - Semantic color aliases
- `packages/design-system/tokens/colors/primitives.json` / `primitives.dark.json` - Raw color palette

### Autogenerated files (do not edit)

These legacy frontend files are overwritten by `make design-system`:
- `apps/frontend/src/styles/css/base.css`
- `apps/frontend/src/styles/css/dark.css`
- `apps/frontend/tailwind.base.js`

### Workflow

1. Add or update a token in the relevant `tokens/colors/*.json` file
2. Run `make design-system` -- this regenerates and copies the output to the deprecated legacy frontend
3. Reference the new token in Tailwind classes (e.g. `bg-badge-blue-bg`) or in component CVA variants

The production Next.js app in `apps/web` does not use these generated Clafoutis files. Its Tailwind v4 theme tokens live in `apps/web/app/globals.css`.

### Adding a new badge variant example

In `components.json` under `badge`, add:
```json
"blue": {
  "bg": { "$type": "color", "$value": "{colors.blue.300}" },
  "text": { "$type": "color", "$value": "{colors.blue.1100}" }
}
```
Add the matching dark override in `components.dark.json`, then run `make design-system`.
Then add the CVA variant in `apps/frontend/src/components/ui/badge.tsx`.

## Smart Contract Storage Layout

The contracts use the Diamond proxy pattern (EIP-2535). All state lives in `AppStorage`, a struct
stored at a fixed `keccak256("taskmarket.appstorage.v1")` slot in `src/libraries/LibAppStorage.sol`.

When adding new state variables:

- **Append only**: new variables must be added at the END of the `AppStorage` struct, never inserted between existing fields
- **No `__gap` needed**: the struct is at a fixed `keccak256` slot; appending is always safe with no slot budget to track
- Never reorder, rename, or remove existing fields between upgrades
- New fields zero-initialise by default; use lazy-init in the facet function body if a non-zero default is needed
